## BUG-001：文档详情页加载失败，阻塞解析主流程

- 严重程度：高
- 影响范围：文档详情、解析、清洗、分块、批量生成
- 复现步骤：
  1. 登录默认项目“压气机知识抽取”。
  2. 上传 `航空发动机燃烧室参数化设计_贾文杰.pdf`。
  3. 在文档列表中点击该文件名或“详情”。
  4. 等待页面加载完成。
- 预期结果：显示文档元数据、默认解析器和“发起解析”等操作按钮。
- 实际结果：页面先长时间显示“加载中…”，随后显示“文档不存在”，并弹出“加载文档详情失败”。同样现象也发生在已有文档 `2606.00097v2.pdf` 上。
- 证据：
  - 上传成功，列表显示文件名、`已上传`、8 页、2.2 MB；新文档 ID 为 `8fccf126-e64f-431f-aba9-448cf1d0f69d`。
  - 浏览器对 `GET /api/projects/{pid}/documents/{did}` 记录为 `net::ERR_ABORTED`，详情页因此没有设置文档状态。
  - 使用同一服务和有效登录会话直接请求该详情接口返回 HTTP 200，文档确实存在；API 日志也记录该 GET 为 `200 OK`。
  - 清空 Web 会话后重新登录、重新进入详情页仍可复现。
- 影响：用户无法从 Web 界面点击“发起解析”，指定 PDF 的解析及后续清洗、分块、生成流程全部被阻塞；“文档不存在”提示也会误导用户判断为数据丢失。

## BUG-002：任务 WebSocket 反复在握手阶段断开

- 严重程度：中高
- 影响范围：任务浮动面板、任务实时状态推送
- 复现步骤：
  1. 登录并进入默认项目。
  2. 在文档、设置、模板、候选、数据集、基准集、导出、任务、监控等项目页面之间连续导航。
  3. 查看浏览器控制台和 API 日志。
- 预期结果：项目级 WebSocket 保持稳定连接；任务状态变化通过 WebSocket 推送，控制台无重复错误。
- 实际结果：浏览器反复报错 `WebSocket ... failed: Connection closed before receiving a handshake response`。本次会话共出现 21 条同类错误；API 日志对应连接多次出现 `WebSocket ... [accepted]` 后立即 `connection closed`。
- 影响：实时任务状态推送不可靠；页面仍可通过 HTTP 查询显示部分状态，但任务处理中的实时反馈可能丢失，并持续污染控制台。

## BUG-003：服务刚启动后首次进入项目列表可能 15 秒超时

- 严重程度：中
- 影响范围：首次登录后的项目列表
- 复现步骤：
  1. 按推荐脚本启动项目后立即打开 Web。
  2. 使用 `admin / admin123` 登录。
  3. 等待跳转到项目列表。
- 预期结果：登录后直接显示默认项目。
- 实际结果：首次加载期间项目列表停留在“加载中…”，随后显示“加载失败：请求超时（15s）”；浏览器记录项目列表 GET 多次 `net::ERR_ABORTED`。
- 复核：API 完成预热后刷新页面可以正常显示项目列表，说明服务并非不可用，而是前端首次请求的超时/重试策略不足。
- 影响：新用户首次启动后容易误以为项目初始化失败，需要手动刷新才能继续使用。
